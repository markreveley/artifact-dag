# research/

Dated surveys of what exists outside the repo: tools, projects, papers,
with what each one is, how it was checked, and where the facts came from.
A survey reports; it does not recommend. What the repo should do about it
is an analysis in `md/analysis/` that links to the survey.

**Belongs here:** a survey of tools or prior work, with sources and the date
each was checked; the material it rests on (excerpts, file lists).

**Does not:** recommendations or findings about this repo (`md/analysis/`),
open questions (`next-operator.md` or a plan), anything re-checked later (a
later survey is a new file that links to this one).

**Names:** `YYYY-MM-DD-<slug>/<slug>.md`. The folder holds its material.

**Form:** the analysis header block (Date, Question, Sources read, Method
caveat), then numbered sections: what was surveyed, one section or table row
per candidate, and the facts with links and dates.
